Key data flows

Article ingestion (every 5 min)

1Worker polls active sources that are due for refresh
2Source-specific fetcher retrieves raw articles
3Scorer computes relevance × recency: term weights (0.5–2.5) × exp(−age/24h)
4UpsertArticle writes to Postgres; ON CONFLICT updates score so it re-scores on next cycle
5Redis cache for /api/feed and /api/digest expires naturally (5 / 15 min TTL)

Feed request

1Client calls GET /api/feed with optional limit, offset, source, q params
2Handler checks Redis for a cache hit on the exact query key
3On miss: queries Postgres with tsvector full-text search + score + date ordering
4Result written back to Redis and returned as JSON

Email subscription

1User POSTs email to /api/subscribe
2Store upserts subscriber with random 64-char token; handles re-subscribe / pending states
3Mailer sends confirmation email via Resend with confirm link
4User clicks link → GET /api/subscribe/confirm?token=… → confirmed=true
5Redirects to /?subscribed=1 for frontend toast

Daily digest email

1Scheduler goroutine wakes at next DIGEST_HOUR UTC (default 08:00)
2Fetches top 20 articles from last 24h via DailyDigest query
3Fetches all confirmed, active subscribers
4Sends one HTML email per subscriber via Resend REST API with personalised unsubscribe link
